# Chorus roadmap

Chorus prioritizes durable local conversations, predictable configuration and observable native Agent execution.

## 0.6.0

- Native Codex and Claude authorization/question cards, bounded waiting and explicit deferred-question continuation.
- Reported-usage budgets stop further dispatch while active tasks finish; retries retain round spend.
- Process-tree cleanup, timeout/result precedence and Unicode/BOM stream boundaries with real process stress checks.
- Room-owned host roles, CLI avatars and packaged Windows uninstall launchers.
- Follow-up acceptance: real-account interactive tools across supported Agents, long-duration memory/disk behavior, Windows 10 hardware. Kimi and other adapters without a verified interactive mapping retain explicit compatibility limits.

## 0.5.1

- Chinese and English interfaces with persistent language selection.
- Model discovery, model-specific reasoning controls and explicit CLI compatibility.
- Searchable room/member selection, reusable pricing tables and direct skill-reference removal.
- Consistent working-directory and permission displays.
- Windows installer, uninstall launcher and portable zip; Ubuntu deb and zip; curated public source packages.

## Validation

Unit tests, real Electron UI checks and isolated packaged startup cover different boundaries. Native model connectivity and full tool execution require separate evidence. A discovered model is not a guarantee of account access.

Windows and Ubuntu CI exercise the same UI checks and packaged startup. Ubuntu also verifies ZIP sandbox setup, Debian installation and removal. Physical desktop hardware, individual accounts and long-running workloads need ongoing verification.

## Native boundaries

Missing context, cache or protocol phase data remains unknown. Native extension enablement depends on the CLI. Unverified noninteractive protocols are not presented as working integrations. Credentials and local conversations are excluded from release inputs.
